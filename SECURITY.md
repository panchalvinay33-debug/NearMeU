# NearMeU Security Policy

## Private reporting

Do not publish credentials, signing material, App Check debug tokens, Firebase exports, user data or exploitable security details in public issues.

The repository owner should use a private communication channel for vulnerability reports until a dedicated security contact is published.

## Protected material

The following must never be committed or pasted into GitHub issues, pull requests, logs or chat:

- Android keystore files or Base64 keystore contents
- Keystore alias or passwords
- Firebase service-account keys
- `.env` secrets
- App Check debug tokens
- Exported Authentication, Firestore or Storage user data
- Private local database or media backups

## Release integrity

- Production artifacts must be generated by protected GitHub Actions workflows.
- Unsigned production releases must be rejected.
- Permanent signing fingerprints must be verified before release.
- Changes to authentication, App Check, rules, signing or account deletion require a focused pull request, green CI and physical-device verification.

## Response priorities

1. Revoke or rotate exposed credentials immediately.
2. Restrict backend writes when unauthorized access is suspected.
3. Preserve logs and take a current-state backup.
4. Deploy safe rules or roll back to the last verified baseline.
5. Test recovery in staging before restoring production.
6. Document the incident without including secrets or private user data.
