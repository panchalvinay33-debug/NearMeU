# NearMeU Production Readiness Audit

Status: active audit on `audit/production-readiness`

## Scope reviewed

- Android package, manifest, backup policy, cleartext policy and release signing
- Firebase Android project/package/OAuth configuration
- Google Sign-In failure handling and certificate fingerprint diagnostics
- App Check startup behavior
- Firebase Messaging registration, revocation and notification routing
- Trusted Cloud Function reads and device-cache fallbacks
- Private image/video preparation, size limits, metadata stripping, upload confirmation and outbox recovery
- SQLCipher local chat storage, per-account encryption key handling and account cleanup
- Trusted account deletion sequencing
- CI coverage for Flutter, Cloud Functions and Firebase rules
- Repository documentation and obsolete repair tooling

## Confirmed safeguards

- `com.nearmeu.nearmeu` is consistently used by Android and Firebase configuration.
- Production release builds require private signing material and refuse unsigned release output.
- Signed release metadata records upload-certificate SHA-1 and SHA-256 without exposing the keystore.
- Firebase config validation checks project id, package name, Android OAuth client, web OAuth client and SHA-1 format.
- Raw Google Sign-In exceptions are no longer exposed to users.
- App Check and notification initialization failures no longer prevent the primary UI from launching.
- Android backups and cleartext HTTP are disabled.
- Image EXIF metadata is stripped during compression.
- Private media has explicit image/video size and video-duration limits.
- Private media is copied into app-private storage before upload and uses `private,no-store` cache metadata.
- Media uploads use a pending local outbox record, trusted callable confirmation and recovery after uncertain network outcomes.
- Chat content is stored in a per-user SQLCipher database with a random key kept in secure storage.
- Account deletion performs trusted backend deletion before best-effort local cache removal and session cleanup.
- Device tokens are registered and unregistered through trusted callable functions; local FCM tokens are revoked on logout.
- Flutter analysis/tests, Functions tests and Firestore/Storage emulator rules tests are enforced in CI.
- Changed Dart files now use formatter exit enforcement, so formatting drift fails CI.
- PR workflow concurrency is keyed by PR identity so newer commits cleanly supersede older runs.

## Notable design observations

- Notification permission is requested during notification-service initialization. This is functional but should be evaluated during physical UX testing; Android users may respond better after onboarding explains the value of notifications.
- Chat preview has a direct Firestore fallback after trusted callable failure. Its safety depends on deployed Firestore rules remaining aligned with the tested repository rules. Production should prefer the callable path and treat fallback behavior as degraded mode.
- Nearby candidates deliberately do not use a Firestore fallback; this avoids exposing broader location/profile queries when the trusted backend is unavailable.
- Developer logs contain exception objects and stack traces but no deliberate message body, media bytes, token value or user profile payload in the reviewed paths. Release telemetry remains governed by the telemetry policy.
- Media confirmation distinguishes definitive rejection from uncertain network state, preserving an outbox record when backend completion cannot be proven.

## Merge gate

Do not merge or distribute a build until:

- the latest PR quality workflow is green;
- all code review findings are resolved;
- external Firebase/Play/GitHub environment checks are recorded;
- a signed release artifact is generated from `main`;
- certificate fingerprints are matched;
- physical-device acceptance tests pass.

This document records source-level findings. It is not evidence that Firebase or Play Console currently contains the matching deployed configuration.
